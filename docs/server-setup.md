- **Служба**: `ssh.service` (классический режим, socket-активация отключена)

Изменённые директивы:

| Директива | Значение | Примечание |

## 8. Веб-сервер

- **Устанавливаемый пакет**: `nginx` (версия 1.28.3)
- **Служба**: `nginx.service` (главный процесс от `root`, рабочие от `www-data`)
- **Путь к конфигурации ресурса**: `/etc/nginx/sites-available/devops-site`
- **Символическая ссылка**: `/etc/nginx/sites-enabled/devops-site`
- **Каталог ресурса**: `/var/www/devops-site`, владелец `devops:devops`, права `755` для каталога и `644` для файлов.

### Сертификаты TLS

- **Путь к сертификату**: `/etc/ssl/certs/devops.crt` (права `644`, владелец `root`)
- **Путь к приватному ключу**: `/etc/ssl/private/devops.key` (права `600`, владелец `root`)
- **Команда формирования сертификата**: 
  `sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 -keyout /etc/ssl/private/devops.key -out /etc/ssl/certs/devops.crt -subj "/CN=devops.local" -addext "subjectAltName=DNS:devops.local"`
- **Срок действия**: 365 дней.

## 10. Ansible

В данном разделе описана конфигурация Ansible, используемая для воспроизводимой настройки удалённого сервера и развёртывания контейнеризированного приложения.

- **Расположение проекта**: Проект Ansible расположен в репозитории `devops-course-2026` в каталоге `ansible/`. Управляющий узел — хостовая система с Linux, управляемый узел — виртуальная машина `devops-vm`.

- **Управляющий и управляемый узлы**:

| Роль | Система | Описание |
|------|---------|----------|
| Управляющий узел | WSL (Ubuntu) | Выполняет `ansible-playbook`, хранит inventory и ключи |
| Управляемый узел | VM `devops-vm` | Принимает SSH-подключения, выполняет модули |

- **Inventory**:

Используются два файла инвентаря:

- **`inventory/bootstrap.ini`** — первичный запуск от имени пользователя `student` с использованием пароля (через `--ask-become-pass`). Применяется только один раз для создания пользователя `devops` и настройки ключей.
- **`inventory/prod.ini`** — последующие запуски от имени пользователя `devops` по SSH-ключу `~/.ssh/devops_vm`. Пароль не запрашивается.

- **Учётные записи**:

  bootstrap — пользователь `student`, существует на чистой VM, используется для первичной настройки.
  prod — пользователь `devops`, создаётся ролью `ssh`, имеет беспарольный `sudo` (`NOPASSWD`) для неинтерактивных запусков.

- **Роли и их ответственность**:

| Роль | Ответственность |
|------|-----------------|
| `base` | Проверка ОС, базовые пакеты, официальный репозиторий Docker, служба Docker |
| `ssh` | Создание пользователя `devops`, установка SSH-ключа, настройка `sudo`, hardening SSH, UFW |
| `nginx` | Установка Nginx, настройка reverse proxy, активация сайта, проверка конфигурации |
| `app` | Загрузка образа из GHCR, запуск контейнера, проверка `/health` |

- **Параметры развёртывания**:

| Параметр | Значение |
|----------|----------|
| Адрес образа GHCR | `ghcr.io/dzemlarisa/devops-ci-app` |
| Полный SHA | `981ee817d475cf503674b23f77dad1224f99360f` |
| Порт контейнера | `5000` (публикуется только на `127.0.0.1`) |
| Health endpoint | `http://127.0.0.1:5000/health` |
| Внешний доступ | через Nginx на порту `80` |

- **Команды запуска**:

Первичный запуск (bootstrap):
```bash
cd ansible
ansible-playbook -i inventory/bootstrap.ini site.yml --ask-become-pass
```

Повторный запуск (prod):

```bash
cd ansible
ansible-playbook -i inventory/prod.ini site.yml
```

Read-only аудит:

```bash
cd ansible
ansible-playbook -i inventory/prod.ini verify.yml
```
